# R14：30 个通信类历史 PR 的双卡盲测

## 结论

R14 达到“有提升再提交”的门槛。在同一批 30 个 PR、同一组冻结证据上，新的
communication contract/disposition split 获得 `11/30` exact（36.7%），旧路数“技术
contract 通过则 accept，否则一律 check”为 `6/30`（20.0%），提升 16.7 个百分点。

改善仍集中在 `check`/`reject`：12 个冻结非 accept 中，新路数命中 6 个，旧路数命中 1 个；
10 个 reject 中 6 个正确，precision 为 60%。两种路数的 accept/non-accept binary 都为
`14/30`（46.7%），没有提升。机器锁定为 18 accept、2 check、10 reject；oracle 为 8 accept、
2 check、20 reject。

本轮第一次把 `technical_contract` 与 `disposition_prediction` 并列锁定。它避免了把成熟历史
PR 的“缺一项验证”一律写成 check，但两个机器 check 仍均未命中；oracle 的两个 check 是
Megatron #6963/#6973，均为 30 天内且 14 天内有最终 head 真人反馈的新 PR。由于盲测输入不含
review，active review 本身仍是低可识别标签。

R14 不使用权重分数，不能声称 merged PR 取得正式 `>=85` ProjectFit；这里只审计离散标签。

## 结果摘要

| 指标 | 同队列旧路数 | R14 | 变化 |
|---|---:|---:|---:|
| Exact label | 6/30（20.0%） | 11/30（36.7%） | +16.7 pp |
| Binary accept/non-accept | 14/30（46.7%） | 14/30（46.7%） | 0 pp |
| 12 个冻结非 accept 的 exact | 1/12（8.3%） | 6/12（50.0%） | +41.7 pp |
| Reject precision | N/A（0 个 reject） | 6/10（60.0%） | 可测 |
| Check precision | 1/12（8.3%） | 0/2（0%） | 数量显著收窄，仍未命中 |
| Merged 中机器直接 accept | 5/8 | 5/8 | 0 |

发布理由是同队列 exact 与目标 check/reject 指标提升，不是整体准确率已足够高。

## 队列与盲测协议

队列严格为 30 例，vLLM、SGLang、FlashInfer、Megatron、TorchTitan、verl 各 5 例。选择阶段只
使用标题、changed paths、变更规模、创建时间和精确 base/head SHA，不读取 state、merge、CI、
label、review 或 comment。读取候选正文与 diff 前已经冻结逐例 claim、风险矩阵和 closure test。

30 例均完成 exact-source 分析；可执行的候选测试在远端精确 head 上运行，通信关键路径再以
`2×NVIDIA A100-SXM4-40GB` 做 NCCL、P2P、collective 数值和生命周期探针。所有机器判断与证据
binding 先写入 lock set，之后才读取 GitHub disposition 和真人反馈。

解盲时为 8 merged、2 closed-unmerged、20 open；oracle 按冻结规则将 merged 记 accept、
closed-unmerged 记 reject，只有 30 天内且最近 14 天有最终 head 明确真人反馈的 open PR 记
check，其余 open 记 reject。

### 候选正文污染处置

SGLang PR 正文嵌入动态 `pr-states` CI 区块。获取过程中有一个区块曾短暂暴露，随后在任何逐例
判断前加入确定性清洗，5 个案例共 5 个区块全部移除；原始 bundle、清洗后 bundle 和清洗清单
分别哈希保留。判定脚本只绑定清洗后的 contract probe，并在 lock set 中显式记录该污染事件。

- Megatron #6200 的候选路径和 power-of-two pre-scale 数值误差均为 0；#7000 固定 packed P2P

  与 Shard(0)/Shard(1)，两 rank 参数和 momentum 均与参考完全一致；#3955 精确两-rank

## R15 前瞻迭代

R15 严格保持 30 例：20 个通信类案例完成通信 50 例 tranche，再加入首批 10 个训练类案例。
具体规则已冻结在 `policy-iteration-r15.json`，不会回写 R14 判断：

1. 选择只使用 `<=30` 天的 prospective 样本或 `>=90` 天的 mature 样本，排除 31–89 天项目
   尚未沉淀的 resolution gray zone。
2. `check` 必须同时满足近期、主方向已证明、最多 4 个 changed files、有候选闭环测试、仅一个
   可执行 residual、无 superseding/可达反例；技术 bounded-gap 本身不再足够。
3. 对最多 3 文件的成熟 target-hardware bug fix，若候选有目标硬件覆盖、源码 invariant 闭合且
   无 exact 反例，不得仅因 evaluator GPU 架构不符而 reject；大型新硬件 feature 不适用。
4. 技术 reject 必须按合法配置 → production reachability → exact failure 排序；仅缺 E2E 记
   unresolved technical，不伪造成失败。
5. 继续分别锁 `technical_contract` 与 `disposition_prediction`，解盲结果只用于下一轮。
