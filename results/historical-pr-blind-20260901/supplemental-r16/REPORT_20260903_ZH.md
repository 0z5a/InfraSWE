# R16：30 个训练类历史 PR 盲测

## 结论

R16 达到“有提升再提交”的门槛，但绝对准确率仍偏低。冻结判断为 `21 accept / 2 check /
7 reject`，oracle 为 `14 accept / 0 check / 16 reject`。同一队列 exact 从旧路数的
`9/30`（30.0%）提高到 `12/30`（40.0%），提升 `+10.0 pp`；accept/non-accept 二分类
仍为 `13/30`（43.3%），没有提升。

本轮 check/reject 区分有局部提升：7 个 reject 命中 3 个（42.9%），旧路数对同一批冻结
非 accept 全部给 check，因此 exact 为 0；新路数在 9 个冻结非 accept 中命中 3 个。两个
check 均未命中，说明“新且改动小”仍不足以表示“明确在审”。R17 将 check 再收紧到同时具有
候选自带核心测试和明确 readiness 信号；只有年龄而没有 review-ready 证据的候选不再进入 check。

R16 不使用权重分数，因此不能声称 14 个 merged PR 获得正式 `>=85` ProjectFit。技术 contract
与历史 disposition 继续双轨保留：例如 slime #2010 的数值/梯度和 A100 显存收益是精确技术通过，
但其长期 open disposition 仍按用户指定 oracle 记 reject；反之 Megatron #5134/#5169 与 slime
#1969/#2020 历史 merged，也不会回写冻结前的技术证据。

## 队列与盲测边界

R16 是第一组完整 30 例训练队列，每个项目 6 例：Liger、Megatron、slime、TorchTitan、verl。
初始 metadata-only 锁发现一个 inference-only 假锚点和一个重复候选后，先冻结一般化修订规则，
再生成 canonical amended selection。修订前后均未读取正文、diff、状态、review、评论、CI 或标签。

逐例 claim、matrix、runtime 与 closure 在正文/源码获取前冻结。之后只获取标题、清洗后的正文投影、
精确 base...head compare 和冻结路径文件；PR 状态及人类反馈在 `machine-judgment-locks.json` 写入后才
reveal。30 个 head 均与选择锁一致，源码无冲突标记；verl #6558 在 reveal 前即被静态解析与
`py_compile` 独立识别为语法错误。

远端实例为 `2×NVIDIA A100-SXM4-40GB`。所有执行先切换到 `refs/r16/pr-*` 并核对 HEAD SHA。
Blackwell、TransformerEngine 和八 rank 专用路径没有伪装为已执行；缺失能力分别记录为 target、
dependency 或 topology gap。

## 关键实测

- Liger #1204 通过 322 个 DPO 公式/梯度用例；#1202 通过 69 个 GRPO 用例；#1208 的实际
  Triton autotune 前后向矩阵 24/24 通过；#1253 GroupNorm 5/5 通过。
- Liger #1413 的 A100 回归在超时前通过 6 个 fused-MoE case，但核心 B300/sm_103 dx 修复未在
  evaluator 硬件上执行，因此技术结论保持 bounded-gap。
- Megatron #7021 的参数、router bias 和 pre-wrap hook 归属探针通过；#5145 内存公式测试、#5162
  TE CE guard 两分支测试均通过。#5134 的候选 checkpoint 测试硬编码要求 8 ranks，1/2 rank
  运行都在合法 topology 前置条件停止，未误记为功能失败。
- slime #2010 在相同张量和梯度 oracle 下，base 首个 yield 峰值为 `163,577,856` bytes，head 为
  `46,137,344` bytes，下降 71.8%；嵌套 fully-async rollout 排序得到稳定的 `2,5,7`。
- slime #2014 的 7 个 filter contract、#2015 的 3 个 offload lifecycle、#1969 的 3 个
  safetensor writer、#2020 的 2 个 node-writer 测试均通过。
- TorchTitan #4358 通过 8 个 replay/trainer/config 定向测试；#3523、#3534、#3533、#3530
  的候选测试均通过。#3538 只运行三个真正改为依赖默认方向的 call site，3/3 通过；全文件中
  无关的 23/24 metadata 计数不被当作候选反例。
- verl #7697 通过 29 个 invalid-tool/config 用例；#6564、#6574、#6560 分别通过 3、8、7 个
  定向测试。#6558 的精确 head 在 `ray_trainer.py:400` 有未闭合括号，candidate collection 与
  `py_compile` 均失败，是本轮最强 reject 反例。#6598 没有可运行测试且正文仍是空模板。

## R17 前瞻迭代

R17 保持 30 例：补完最后 `10 training`，并开始 `20 inference`；四个推理主 draft 各 5 个：
vLLM、SGLang、TensorRT-LLM、FlashInfer。R18 及以后仍不提前选样。

1. check 除 `<=7` 天、`<=8` 文件、一个 residual 外，必须有 candidate-owned 核心测试，且正文
   不得明确声明 human review/CI 未完成；只有年龄不再足够。
2. 正文明示未人工复核、仍为 draft 或尚未请求 CI 时，disposition 默认 reject；技术结果另存。
3. 成熟 feature/algorithm 无候选测试默认 reject，除非有 evaluator exact base/head 或结构化例外。
4. deprecation/config container 的纯结构迁移，在旧 symbol 全仓归零、call site 全枚举、import/compile
   与受影响测试通过时可 accept；不能套用于数值、状态布局或 collective 算法。
5. checkpoint/export writer 以 tensor 唯一性、shard/index 完整性、atomic finalize 与 reload parity 为
   artifact closure，不再机械要求 optimizer step。
6. metadata-only 选样限制同项目高重叠 stack：标题前缀相近且生产路径 Jaccard `>=0.5` 时最多取 2 个。
7. scheduler/memory/concurrency 仍要求真实 runtime，纯资源算术或 mock 不足；SyntaxError、冲突标记、
   import failure 与候选 exact failure 继续最高优先级。

工作量账本：已完成 `50 communication + 40 training`；剩余 `10 training + 100 inference`。
