# R18：30 个推理类历史 PR 盲测

## 结论

R18 达到“有提升再提交”的门槛。冻结判断为 `21 accept / 3 check / 6 reject`，
oracle 为 `13 accept / 1 check / 16 reject`。同一队列 exact 从旧路数的 `12/30`
（40.0%）提高到 `14/30`（46.7%），提升 `+6.7 pp`；冻结为非 accept 的 9 例中，
exact 从 `1/9` 提高到 `3/9`。6 个 reject 命中 3 个（50.0%），3 个 check 均未命中。

二分类仍为 `18/30`，没有提升；13 个最终合并案例中有 11 个冻结为 accept。R18 说明
target-gap transfer 能减少“因为本地缺目标架构或生成 bindings 就拒绝”的假阴性，但也说明
仅凭近期、范围有限、技术上可修复，无法可靠推出历史 disposition 为 check。R19 因而取消
“近期技术可修复即可 check”的捷径，继续重点学习 check/reject 的历史区分。

## 盲测边界与执行

R18 在 metadata-only 阶段冻结 30 例，分配为 `vLLM 8 + SGLang 8 +
TensorRT-LLM 7 + FlashInfer 7`。selection 与 test plan 锁定前不可见正文、源码、状态、
review、评论、CI 和标签；其后只获取清洗正文与精确 base...head。判断锁落盘后才揭晓状态和
人类反馈，30 个 head 均与选择锁一致。

远端环境为 `2×NVIDIA A100-SXM4-40GB`。测试使用候选自带用例、title-scoped 聚焦用例和
fail-closed 可选依赖隔离；TensorRT-LLM 的生成 bindings 缺口只记 capability gap。典型证据
包括 SGLang #27181 的 15 个 LoRA overlap 单测、#27183 的 9 个 Gemma4 YOCO 单测、
TensorRT-LLM #14765 的 18 个 LoRA layout 单测、vLLM #44450 的 2 个 LoRA runner 用例以及
#44518 的 5 个 native audio attention 用例全部通过。测试通过只支持 technical contract，
不直接泄漏或替代历史 disposition。

## R19 前瞻迭代

1. 不再因“近期、技术上可修复”直接给 check；没有可见的独立 review 活跃度时，历史
   disposition 与 technical contract 分开表达。
2. 候选自带断言在变更边界稳定失败时优先 reject；仅由目标硬件、生成 bindings 或无关导入
   引起的不可执行仍只记 capability gap。
3. 成熟 PR 的 accept 需要 final-head contract、正负控制和可达集成路径共同支持。
4. R19 轮换项目份额为 `FlashInfer 8 + TensorRT-LLM 8 + SGLang 7 + vLLM 7`，
   不在揭晓后回改 R18 判断。

工作量账本：已完成 `50 communication + 50 training + 50 inference`；剩余 `50 inference`。
