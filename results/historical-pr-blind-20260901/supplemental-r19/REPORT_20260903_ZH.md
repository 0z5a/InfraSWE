# R19：30 个推理类历史 PR 盲测

## 结论

R19 达到“有提升再提交”的门槛。冻结判断为 `18 accept / 0 check / 12 reject`，
oracle 为 `15 accept / 0 check / 15 reject`。同一队列 exact 从旧路数的 `9/30`
（30.0%）提高到 `15/30`（50.0%），提升 `+20.0 pp`；冻结为非 accept 的 12 例中，
exact 从 `0/12` 提高到 `6/12`。12 个 reject 命中 6 个（50.0%）。

二分类仍为 `15/30`，没有变化；提升完全来自把旧路数笼统的 check 更准确地拆成 reject。
本组 15 个最终合并案例中只有 9 个冻结为 accept，说明 R19 的 reject 增益以较高 merged
假阴性为代价。尤其四个近期样本最终全部非 accept，证明近期技术闭环不能直接映射为 accept；
但成熟 final-head、有正负控制且仅受本地能力缺口阻断的案例又不应被一律拒绝。R20 因此加入
merged-recall guard，并强化语言中立、路径中立的窄不变量证据。

## 盲测边界与执行

R19 在 metadata-only 阶段冻结 30 例，分配为 `FlashInfer 8 + TensorRT-LLM 8 +
SGLang 7 + vLLM 7`。selection/test-plan、清洗正文和精确 base...head、静态与远端测试、
判断锁、最终 reveal 的顺序未改变；判断前没有请求状态、review、评论、CI 或标签字段。

远端环境继续使用 `2×NVIDIA A100-SXM4-40GB`，两条 GPU lane 执行项目原生用例和
title-scoped 聚焦用例。所有可选依赖 shim 均 fail-closed；未触达候选断言的环境故障不记为
pass。R19 最有价值的反例是：即使近期 PR 的候选测试或生产路径技术上闭环，它仍可能因优先级、
ownership、重复实现等 blind source 不可见因素长期开放或关闭。这促使终局模型保留
`technical_contract` 与 `historical_disposition` 双输出。

## R20 前瞻迭代

1. 近期 PR 在 blind source 中缺少独立人类活动时，历史 disposition 默认 non-accept；技术通过
   单独保留，不能直接冒充 review-active check。
2. 成熟 PR 若 final-head contract 完整、有正负控制，并有候选集成路径或独立窄不变量支持，
   则目标架构、生成 bindings 与测试语言差异不应单独触发 reject。
3. 候选自带精确断言失败继续压倒 sibling pass；反之，无关 fixture/import 失败不能污染候选判断。
4. 发布前显式审计 merged accept recall，避免仅靠扩大 reject 数量制造表面 exact 增益。
5. R20 为终局 20 例，四个推理项目各 5 例；冻结后四项目累计各 25 例。

工作量账本：已完成 `50 communication + 50 training + 80 inference`；剩余 `20 inference`。
