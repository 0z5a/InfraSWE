# R20：20 个推理类历史 PR 终局盲测

## 结论

R20 达到“有提升再提交”的门槛，并完成用户指定的 200 个增测 PR。冻结判断为
`15 accept / 1 check / 4 reject`，oracle 为 `11 accept / 1 check / 8 reject`。
同一队列 exact 从旧路数的 `12/20`（60.0%）提高到 `14/20`（70.0%），提升
`+10.0 pp`；冻结为非 accept 的 5 例中，exact 从 `1/5` 提高到 `3/5`。4 个 reject
命中 3 个（75.0%），唯一的 check 未命中。

二分类为 `16/20`，与旧路数相同；提升来自 check/reject 的细分。更重要的是，11 个最终合并
案例全部冻结为 accept，merged accept recall 为 100%。这同时满足“分类有提升再提交”和
merged-recall guard。R20 没有使用加权分数，因此不能把历史标签解释成校准代码质量分，也不能
审计“合并 PR 必须达到 85 分”的旧式分数门槛；这里可审计的更强事实是本轮没有漏掉任何 merged PR。

## 盲测边界与执行

R20 是终局 20 例，`FlashInfer / SGLang / TensorRT-LLM / vLLM` 各 5 例。
selection/test-plan 在 metadata-only 阶段冻结；正文、源码和测试只在选择后开放，状态、review、
评论、CI 与标签只在判断锁后 reveal。四项目在 R17–R20 最终各累计 25 例，没有揭晓后换样或
回改判断。

远端环境为 `2×NVIDIA A100-SXM4-40GB`。关键可复现证据包括：FlashInfer #3461 的 18 个
logits/probs alignment 用例通过，#3465 的 8 MiB workspace offset/alias 探针通过；
SGLang #27257 的候选 parallel-expand 用例在精确 head 触发 `IndexError`，因此正确 reject；
TensorRT-LLM #14869 的 source-extracted Triton 路径同时满足 strided copy 与邻域不变式；
vLLM #44526 的窄 clamp 探针 6/6 通过，证明较宽测试中的旧 fixture 失败与候选无关。

## 终局经验

1. `check` 必须由冻结前允许证据中的独立、非作者人类 review/handoff 支持。机器人 QA、作者自述
   和泛化的“待跟进”文字都不是 check oracle。当前 blind 协议禁止该证据通道时，应显式标记
   `check_observability=unavailable`，不能从代码质量凭空推导 check。
2. 没有独立人类活动时，近期且技术完整的 PR 在历史 disposition 上默认 reject，同时保留
   technical pass；FlashInfer #4879 的真实 check 只能由锁后揭晓的人类反馈区分。
3. 候选自带、变更边界内的精确断言失败直接 reject；sibling pass 或局部实现合理不能覆盖它。
4. 对没有候选测试的成熟 PR，technical accept 至少需要可达集成路径或独立窄不变量；作者回执
   只能作旁证。
5. C++、集成列表、waiver 删除、API schema 和既有矩阵是一等证据；生成 bindings 缺失若未触达
   候选断言，仅是 capability gap。
6. 始终分别输出 `technical_contract` 与 `historical_disposition`，并在发布前显式审计 merged recall。

工作量账本：完成 `50 communication + 50 training + 100 inference`，剩余均为 0；100 个推理
案例中四个主 draft 各 25 个。
