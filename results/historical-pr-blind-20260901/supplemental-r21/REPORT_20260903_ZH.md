# R21：首组 100 个推理类历史 PR 盲测

## 结论

R21 完成新增 500 个推理 PR 计划中的第一组 100 个，`FlashInfer / SGLang /
TensorRT-LLM / vLLM` 各 25 个；与此前 298 个已评分身份零重叠。冻结判断为
`95 accept / 0 check / 5 reject`，oracle 为 `63 accept / 1 check / 36 reject`。

同队列 exact 从旧路数的 `64/100` 提高到 `67/100`，提升 `+3.0 pp`；5 个 reject
命中 4 个，precision 为 80%。二分类为 `68/100`，与旧路数相同。63 个最终合并案例全部在
揭晓前冻结为 accept，merged accept recall 为 `63/63`（100%）。因此本轮达到“有提升再提交”
门槛，收益集中在 check/reject 的细分，没有以牺牲已合并 PR 召回来扩大 reject 数量。

## 执行边界

严格顺序为：metadata-only 发现与选择锁 → test-plan 锁 → 清洗正文和精确 base/head
源码 → 静态分析与远端测试 → pre-reveal 判断锁 → 状态/review 揭晓 → oracle 审计。
选择阶段不读取正文、diff、状态、合并、review、评论、CI 或标签。100 个案例含 96 个成熟 PR
与 4 个近期 PR；源码采集清洗了 23 个带机器维护状态块的正文。

远端环境为 `2×NVIDIA A100-SXM4-40GB`。最终判断只绑定完整主矩阵、按框架版本对齐的重跑、
瞬态 SSH 重跑和 TensorRT-LLM #14343 单例复核；依赖与平台 shim 调试探针没有被混入判断证据。
技术层结果为 `23 pass / 76 bounded-gap / 1 fail`。超时、缺依赖和目标架构不可用保持中性，
只有候选自身的精确断言失败才进入 fail/reject。

## R21 后的前瞻迭代

R21 暴露的主要问题是 32 个 false accept，而不是已合并 PR 的漏召回。项目先验、测试数量和
runtime pass 都不足以安全地作宽泛 reject，因此 R22 只冻结以下窄规则：

1. 普通 PR 单测最多 60 秒，TensorRT-LLM 最多 20 秒；超时记
   `abandoned-time-budget`，中性放弃该 PR，不反复重试。
2. `check` 仅允许给 7 天内、且存在命名非作者 final-head 活动的 PR；只投影事件元数据与派生
   布尔值，不保存 review 文本，不读取状态、合并、CI 或标签。
3. 只把标题开头的显式 `[Draft]` 当作 readiness veto，避免把 speculative draft 等正常术语
   误判为草稿状态。
4. 负先例必须至少两个、同项目、同风险族、通过冻结的相似门槛且全部为 reject；任一相近
   accept 先例都会否决该推断。

上述 `[Draft] + 负先例共识` 对 R21 做留一验证时为 `72/100` exact，仍保持 `63/63`
merged recall；这只是为 R22 选规则，R21 冻结锁没有被回改。
