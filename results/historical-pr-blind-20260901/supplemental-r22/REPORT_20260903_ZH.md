# R22 推理类历史 PR 盲测报告

R22 是 500 个新增推理 PR 计划的第 2 组，共 100 个样本；vLLM、SGLang、
TensorRT-LLM、FlashInfer 各 25 个。选样、源码证据、测试计划、机器判断均在揭晓
PR 结局前冻结。

## 结论

| 指标 | R22 | 同 cohort 旧策略 | 变化 |
|---|---:|---:|---:|
| 三分类精确命中 | 60/100 | 57/100 | +3 pp |
| 二分类方向命中 | 61/100 | 61/100 | 0 pp |
| `check` 精度 | 1/1 | — | 100% |
| `reject` 精度 | 4/10 | — | 40% |
| 已合并 PR 判为 accept | 55/60 | — | 91.7% |

机器判断为 89 accept、1 check、10 reject；揭晓后的 oracle 为 60 accept、2 check、
38 reject。R22 达到“check/reject 区分相对旧策略有提升”的提交门禁，但 reject 仍明显
过度，且漏掉 5 个已合并 PR，不能把 60% 描述为成熟分类器表现。

## 执行证据

- 100 个样本全部形成冻结记录：35 个 exact pass、2 个 candidate-bound exact fail、
  63 个 bounded gap；无未解析判断。
- 普通项目单 PR 最长 60 秒，TensorRT-LLM 最长 20 秒。21 个超时统一记录为
  `abandoned-time-budget`，按中性缺口处理并继续下一项；没有 SSH 失败。
- 主运行之外只纳入三份有明确环境修复价值的正式重跑证据；依赖诊断探针和无提升的
  `upstream-environment-rerun-v3.json` 不进入机器判断。
- 环境适配使 SGLang PR 27165、27059、27155、27026 获得 exact pass；私有模型、
  8-GPU 前置条件、编译扩展缺口和超时项没有无限重试。

## 错误分析与 R23 迭代

R22 的 10 个 reject 中只有 4 个与 oracle 一致。主要误差来自：把 source-complete 的
成熟运行缺口判成 reject；仅凭两个近邻形成负 precedent；以及在 A100 上把 AMD/Hopper
专用测试失败当成候选实现失败。另有一项 review 活动在早期 activity projection 之后、
机器锁之前到达，导致该 recent PR 被误判为 reject。

据此冻结的 R23 前瞻规则包括：

- 在机器判断前即时刷新一次 outcome-free activity projection；`check` 仍只允许给近期、
  final-head 上存在具名非作者实质活动的 PR。
- source-complete 的成熟 PR 不再仅因运行环境缺口而 reject。
- exact failure 只有在候选声明的平台与执行器架构相符时才能触发 reject。
- 负 precedent 至少需要 3 个同项目、同风险、无 accept 邻居的近邻。
- 保留窄范围的 `[draft]`、作者自述未完成和源码完整性 veto。

把这些通用规则仅投影回已揭晓的 R22（不改写 R22 锁）时，精确命中为 65/100，
check 为 2/2，reject 为 3/3，已合并 PR accept recall 为 60/60。该结果只是 R23
规则的回顾性健全性检查，不能冒充新的盲测成绩；规则必须在 R23 新 cohort 上验证。
