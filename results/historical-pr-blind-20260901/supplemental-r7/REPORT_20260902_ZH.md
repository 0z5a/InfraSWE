## 4. 判定解释

### CUTLASS #3427

修复目标本身通过：head 避免在 basis 不同的情况下实例化不可比较的 value equality；新增 metadata-K 断言给出比 base 下游通用断言更直接的诊断。`revise` 只由保留性测试缺失触发，SM120 runtime/performance 作为非阻塞 unresolved 保留。

### Liger #1328

必须区分两件事：

- PR 的目标故障已经被精确复现并由 head 修复；
- 冻结计划要求完整 `fullgraph` 和 zero graph break，而同一路径在更早的 `target_mask.sum().item()` 处仍会 break。

因此结论不是“这个一行 guard 错了”，而是“当前 PR 还不能满足更强的 compile 生命周期合同”。64 iterations × 7 pairs 的 common eager 路径没有性能回退。

### DeepGEMM #389

source 与 AOT 证据高度一致：两条新增 fence 都在目标 stage-rotation XOR 前进入 PTX。H100 无法执行 SM100 Mega-MoE，因此不能把 AOT 推断成动态 race 已消失或性能无回退。ordered policy 规定 blocking unresolved 优先于已知 test gap，最终为 `unresolved`。

### Megatron #6174

host schedule 机制和 changed direct test 均通过。真正决定生产可合并性的 multi-rank FSDP liveness、输出/梯度、step latency 与 peak memory 需要至少两张适配 GPU 和完整依赖；当前单 H100 cell 不具备，故主动 abstain。

### TorchTitan #4032

head 已经不是 trainer 内自动设置环境变量，而是读取配置后打印 shell export 的辅助脚本。计算公式本身通过，但 frozen claim 要求 ROCm-only/no-op/override/error semantics：

- helper/main 不检测 ROCm；
- CUDA/CPU 不是内部 strict no-op；
- 已有用户值只得到提示，若 `eval` 输出仍会被覆盖；
- 4 个测试只覆盖 lane math。

因此 `revise` 是接口/生命周期合同不匹配，不是否定 lane 算法。

### verl #7220

去重初始化逻辑和 `tokenizer_path` 支持是明确收益。阻塞点是配置迁移没有显式兼容边界：旧入口读取 `config.data.trust_remote_code`，新入口只消费 model-scoped 字段；旧 YAML 会静默退回 false。另有 revision、processor kwargs 和直接矩阵测试缺口。

## 5. 锁后 reviewer 对应

最终 strict final-head 人类反馈资格只有 verl #7220 一项。

- verl 的真人 review 正好绑定冻结 head，并精确指出 `data.trust_remote_code` 到 model-scoped 字段的静默行为变化，建议兼容或显式 warning；这与机器阻塞码 `VERL_LEGACY_TRUST_REMOTE_CODE_POLICY_MISSING` 精确对应。作者确认迁移是有意设计，PR 随后合并，所以这里校准的是“风险概念被发现”，不是“机器应预测不合并”。
- TorchTitan 有 5 条明确真人技术反馈，但都针对较早 commit，不满足 final-head 严格资格。其“ROCm 专用逻辑会让 CUDA 用户困惑/不应在 trainer 自动设置”的概念与机器的 backend-scope 发现相关，只能作为诊断对应。
- DeepGEMM 的 review 正文来自自建 `ds-review-bot`；它确认 fence 位置和 all-lane/CTA ordering 正确，但不能记为真人校准。
- Liger 只有作者给出的 before/after，精确复现同一 dtype_out 故障并报告 patched test 通过；可作为独立复现实验的旁证，不是 non-author review。
- CUTLASS 没有非空真人 review 正文；Megatron 没有 final-head 独立技术反馈。
