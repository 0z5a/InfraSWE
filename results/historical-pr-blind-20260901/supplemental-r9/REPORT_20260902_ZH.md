## 3. 判定解释

### CUTLASS #3332

候选对冻结的数值边界合同是正确的：它避免把超出 signed i64 的 Python 无符号整数先经
浮点或错误的 signed literal 路径丢失信息。未运行完整 CuTeDSL compiler 被保留为非阻塞
环境范围，不从 helper probe 外推 production runtime。

PR 后来关闭，是因为 v4.6 release sync 在另一条实现路径上独立解决同一问题。这解释了
为什么“源码候选可接受”和“该 PR 未合并”可以同时成立；这是 disposition confounder，
不是把 outcome 倒灌进机器判定的理由。

### FlashInfer #3950

这项不是只做 AST 存在性检查。远端 A100 cell 用真实 PyTorch tensor 和 public
`checkpoint_restore` 生命周期执行精确 base/head：base 复现目标 failure，head 修复且 flags
完全匹配，普通模式和重复调用 controls 也通过。changed test 直接覆盖内部 protocol 初始化，
独立 probe 补上 public entrypoint。A100 cell 不具备 MNNVL transport 证明能力，因此仍保留
非阻塞范围项。

### SGLang #31346

冻结计划要求“只拒绝一个精确不支持集合”，而不是看到新 `raise` 或新测试就通过。96 项
truth table 同时覆盖 CUDA/HIP、prefill/decode backend、fp8/bfloat16/auto，且校验嵌入正常
配置解析生命周期。该结果与锁后 merged 状态一致。

### SGLang #31349

112 项矩阵验证的是 helper 的确定性、边界、纯度和非法输入，不把新增 test 文件数量当成
正确性代理。锁后作者关闭原因为换用干净分支创建替代 PR，并说明两文件 patch 与证据保持
字节等价。因此本例的 closed-unmerged 不能直接当作候选质量 reject oracle。

### vLLM #48695

机械层面并非全错：缺 nvcc、旧版本、malformed output、OS error、timeout 都能 fail closed。
阻塞问题位于证明对象：任意 FlashInfer cubin 或任意 JIT-cache artifact 只证明“存在某些
FlashInfer 原生产物”，不能证明 selection 即将调用的 FP4 fused-MoE kernel 可用。

机器锁中的阻塞码：

- `VLLM_FP4_KERNEL_SPECIFIC_ATTESTATION_MISSING`；
- `VLLM_FP4_CAPABILITY_BRANCH_TEST_MATRIX_INCOMPLETE`。

揭盲后作者关闭说明确认 `flashinfer-cubin` 不包含 CUTLASS fused-MoE JIT module，并选择等待
上游持久修复而不是维护 vLLM 私有 package/toolchain heuristic。这是本轮最清晰的盲测诊断
命中。

## 4. reviewer 与 outcome 审计边界

旧 reveal 规则曾把 `/bot run tests/gemm` 和 `/rerun-test ...` 计为明确 reviewer feedback。
R9 在锁后统计阶段修正为：slash command 不属于实质技术反馈。重跑后 strict final-head
真人反馈资格为 0，因此不报告 reviewer 命中率。

关闭原因来自作者的 post-lock comments，可以解释 disposition，但不作为 strict independent
review calibration。机器 judgment lock 未改写。

## 5. 与 R8 负对照的关系

R8 的 30 项 coarse static analyzer 把“改了测试且未发现明显静态坏味道”统一映射到 94 分和
`accept_with_scope`，揭盲后只匹配 13/30。它证明两极化本身不能创造判别力，现保留为负
对照，不回写分数或标签。

R9 的变化不是换一套阈值，而是把每个 claim 拆成不同的可证伪合同：

- 数值边界矩阵；
- checkpoint state transition；
- backend/dtype truth table；
- deterministic launch-bound matrix；
- kernel-specific capability attestation。

因此本轮没有 0–100 分，也不执行“merged 必须事后补成 85+”。历史 outcome 只在机器锁后
用于诊断校准。
