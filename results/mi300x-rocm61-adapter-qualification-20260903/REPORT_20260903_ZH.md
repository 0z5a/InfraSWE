# MI300X / gfx942 / ROCm 6.1 适配验证

## 裁决

2026-09-03 在目标 Runpod 主机完成 MI300X 功能与原生路径适配验证：硬件 profile
通过，5/5 attention case 与 7/7 classic kernel 均通过 correctness，所有 attention
case 均观察到 AOTriton `attn_fwd` 原生事件，所有 classic case 均观察到对应 Triton
kernel 事件。

本次状态为 `hardware_qualified_diagnostic`，不是 `hardware_scored`。目标主机的
`rocm-smi --showpids --json` 在前、后两次检查中均报告 9 个既有 PID；修复后的
fail-closed lease guard 因此返回 `LIVENESS_DEVICE_NOT_EXCLUSIVE`。正式 runner 在任何
校准、测量或评分前以退出码 3 阻断，未生成 `score.json`。

## 诊断覆盖

Attention：

- `common-b4-s512-h16-d64-noncausal`
- `common-b2-s1024-h16-d64-causal`
- `common-b1-s2048-h16-d128-causal`
- `boundary-b3-s1000-h12-d64-causal`
- `stress-b1-s4096-h8-d128-causal`

五项均通过数值正确性、动态输入 anti-cache 检查和 AOTriton native trace。

Classic：

- Vector Add、Softmax、LayerNorm、RMSNorm、SwiGLU、RoPE、GEMM

七项均通过数值正确性；profiler 分别观察到 `_vector_add_kernel`、
`_softmax_kernel`、`_layernorm_kernel`、`_rmsnorm_kernel`、`_swiglu_kernel`、
`_rope_kernel` 与 `_matmul_kernel`。计时身份已记录为
`evaluator-owned-hip-events`。

诊断仅使用单 replay、单 matched block 和 1 ms 最小 timed span，用于发现适配错误，
其 latency 明确为 `non-authoritative-diagnostic`，不得用于排名或正式分数。

## RFC 边界

- P0A：租约失败归属 Infrastructure，不改写为 Candidate FAIL。
- P0B：证据来自 evaluator 脚本，ZIP 内含逐文件 SHA-256 manifest；没有把候选输出当作
  verifier authority。
- P0C：硬件、capability/native path、resource lease 与 benchmark cell 分开处理；未知或
  非独占不会静默降级成可评分状态。
- v0.5.1 communication：本次为单 GPU kernel cell，未产生 collective/communication
  capability 或分数主张。
- v0.5.2 memory tiering：本次没有 CPU offload/host tier 目标，不从 MI300X unified package
  推导任何 offload 能力。
- v0.5.3 LLM-as-Judge：本次裁决完全来自确定性检查和 profiler evidence，没有 Judge
  contribution。

## 正式闭环条件

若要从 `hardware_qualified_diagnostic` 升级为 `hardware_scored`，必须先取得能证明目标
GPU 独占的 provider lease/隔离证据，随后再运行正式 runner 的三次 fresh-process replay、
30-block paired timing、独立 profiler sidecar、前后 lease sentinel 与 deterministic scorer。
